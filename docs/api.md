# The API

The web UI talks to the bridge through this API and nothing else; it is the contract between `ui/` and
`src/server/`. REST under `/api/`, JSON both ways; one WebSocket at `/api/events`. The server listens
on `server.host:server.port` (`0.0.0.0:8282` by default, see [config.md](config.md)) and serves the built
UI for every other path.

**Access** is `server.auth` ([config.md](config.md#access)): with `none` (the default) every route is open;
with `password` or `proxy` every route but the three under `/api/auth` answers `401` without a session cookie or
the proxy's header, and the WebSocket upgrade of `/api/events` is refused with `401`.

## Authentication

| Route                   | Answer                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/auth`         | open; `{mode, authenticated, user?, logoutUrl?}` — `user` and `logoutUrl` in proxy mode                                                                                                                                                                                                                                                                                |
| `POST /api/auth/login`  | open; `{password}` → `{mode, authenticated: true}` and the session cookie `mqtt2matter_session`; `401` for a wrong password, `429` after ten failures from the address within 15 minutes, `400` outside password mode                                                                                                                                                  |
| `POST /api/auth/logout` | open; ends the session and clears the cookie                                                                                                                                                                                                                                                                                                                           |
| `PUT /api/auth`         | `{mode, password?, proxyHeader?, proxyLogoutUrl?}`: the access settings, written to the file (the password as its hash) and applied at once; every session ends, the caller gets a new one in password mode. `400` for password mode without a password (none set before), `409` for proxy mode on a request without the header, or when the environment sets the mode |

## Conventions

- A request body is JSON (`content-type: application/json`), at most 8 MB.
- A success is `200` with a JSON body, or `204` without one. An error is `4xx`/`5xx` with
  `{"error": "<message>", "details"?: …}`; a device that does not parse comes back as `400` with
  `details.issues: [{level, path, message}]`, the same shape the validator uses.
- Values matter.js hands out as bigints are strings in JSON; byte arrays are hex.
- A **device** in a request or response is a device entry of [config.md](config.md) — the parsed form
  (every field present, defaults filled) in responses; a request may leave the defaults out. The file is
  written in the compact form (no defaults).
- `:key` is a device key, `:id` a bridge id.

## Status and configuration

| Route               | Answer                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /api/status`   | `{version, uptime (s), running, configPath, mqtt: {url, connected}, bridges: [bridge…], devices: n, importers: ["z2m", …], update: {latest?, newer}}`                                                                                                                                                                                                                                                                                                                                                  |
| `GET /api/stats`    | the statistics popup: `{uptime (s), memoryMb (RSS), heapMb, cpuPercent (of one core), eluPercent (event loop utilisation), lagMeanMs, lagMaxMs (event loop delay), mqttMessagesPerSecond, window (s), devices, endpoints, bridges, bridgesCommissioned, fabrics, mqttConnected, mqttTopics}` — the rates and the event loop figures are averages over a window the server closes every 5 s (since the start until the first one closes), so every viewer reads the same values; the counts are current |
| `GET /api/config`   | `{path, settings, overridden, effective}` — `settings` is the file's top level without `devices` (what the editor saves back), `overridden` the paths the environment sets (`["mqtt.url"]`), `effective` the running values with the MQTT password masked                                                                                                                                                                                                                                              |
| `PUT /api/config`   | body: the `settings` object (`mqtt`, `storage`, `log`, `vendorId`, `productId`, `bridges`, `server`, `presets`, `importers`); validated as a whole; `409` when a path the environment owns would change; answers `{saved: true, restartNeeded: true}` — settings apply at the next start                                                                                                                                                                                                               |
| `GET /api/update`   | `?check=1` asks the registry now (else at most every 6 hours); `{current, latest?, published, newer, checkedAt?, error?, restart: {available, reason?}, update: {available, reason?, requested?, log}}` — `published: false` while the package is not on npm, `log` the last lines of the update helper's log                                                                                                                                                                                          |
| `POST /api/update`  | `{version}`: the registry's newer latest version only; writes the request the root helper takes (README "Restart and update from the UI"); `409` with the reason otherwise (not under the service, not published, not the latest)                                                                                                                                                                                                                                                                      |
| `POST /api/restart` | `{restarting: true}`, then a clean stop with exit code 75, which the service's unit restarts on; `409` when not running as that service                                                                                                                                                                                                                                                                                                                                                                |

The licences of the package — mqtt2matter's own (`LICENSE`, `NOTICE`) and the third-party ones of the runtime
dependencies and of what the UI bundle contains — are a static file of the built UI, `/licenses.json`:
`{self: {name, version, license, text, notice}, runtime: [package…], ui: [package…]}`, each package
`{name, version, license, repository?, text?}`; generated by `npm run build` from `node_modules`.

## Devices

| Route                         | Answer                                                                                                                                                                                                                                                                   |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /api/devices`            | `[{key, name, enabled, deviceTypes, endpoints: n, source, bridge, number, reachable, built, violations, errors, warnings}]` — `number` is the Matter endpoint number, `built` whether the endpoint exists in a bridge, `errors`/`warnings` the static validator's counts |
| `GET /api/devices/:key`       | `{key, device, issues: [{level, path, message}], built, bridge, number, state}` — `issues` are the static ones plus the running endpoint's conformance violations; `state` as below, or absent when not built                                                            |
| `PUT /api/devices/:key`       | body: the device. Creates or replaces: the file is written, the old endpoint (if any) is removed, the new one built and wired without a restart — the endpoint number stays with the key. A device with validation errors is saved but not built. Answers like `GET`     |
| `DELETE /api/devices/:key`    | removes the device from the file and the bridge; `204`                                                                                                                                                                                                                   |
| `GET /api/devices/:key/state` | `{<endpointId>: {number, state: {<Cluster>: {<attribute>: value}}}}` — the live Matter state of every endpoint of the device; `404` when not built                                                                                                                       |
| `POST /api/validate`          | body `{device}`; answers `{ok, issues}` from the schema and the static validator, nothing is saved                                                                                                                                                                       |
| `POST /api/check`             | body `{}` for the whole configuration or `{devices: {<key>: device}}`; runs the strict dry run of `mqtt2matter --check` (a throw-away node, no network) and answers `{ok, devices: {<key>: issues[]}}` — only devices with issues are listed                             |

## The mapping editor

| Route               | Answer                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/preview` | `{direction: "status", half, payload, attribute?, topic?}` → the payload through the status half's steps; `{direction: "command", half, value, attribute?, fields?}` → the value through the command half's. Answers `{ok, stages: [{step, ok, value?, reason?}], result?, reason?}`; the stages are `extract`, `template`, `map`, `unit`, `scale`, `attribute` (status) and `value`, `scale`, `format`, `wrap`, `payload` (command), only those the half uses. `attribute` (`Cluster.attribute`) gives the attribute's shape (enum names, bitmaps) |
| `POST /api/publish` | `{topic, payload, retain?, qos?}` → publishes; `{published: true}`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `GET /api/topics`   | `?prefix=` optional; `[{topic, payload, retain, ts}]` — the topic cache: every topic seen on the subscriptions (`server.topics` plus the mappings'), payloads cut at 16 kB, sorted                                                                                                                                                                                                                                                                                                                                                                  |

## Bridges

| Route                                    | Answer                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/bridges`                       | `[{id, port, online, commissioned, pairingCodes: {manualPairingCode, qrPairingCode}, devices: n, fabrics: [fabric…], windowStatus}]` — `windowStatus` 0 closed, 1 enhanced window open, 2 basic window open; a fabric is `{index, label, vendorId, vendorName?, nodeId, rootNodeId, fabricId, compressedFabricId, sessions, subscriptions, lastInteraction?}`: `vendorName` the controller of a known root vendor id (Apple Home, Apple Keychain, Google Home, Amazon Alexa, Home Assistant, SmartThings, …), `nodeId` the bridge's node id in the fabric, `rootNodeId` the controller's, `compressedFabricId` hex, `sessions` the active sessions and `subscriptions` their subscriptions, `lastInteraction` ms since the epoch |

## Adopt

The importers ([importers.md](importers.md)) describe devices from a source; the server subscribes their topics
(`zigbee2mqtt/bridge/devices`, `…/groups`, `homeassistant/#`), hands them every message, and asks them for the report over the
devices as they stand in the file. The server moves results into the file and the running bridge; the logic —
baseline, the user's edits, conflicts, orphaning — is the importer's.

| Route                        | Answer                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/adopt`             | `{importers: [kind…], entries: [SyncEntry…]}` — the importer's `diff` over the file's devices; each entry is `{importer, key, kind: "device" \| "group", name, status, conflicts: [{path, user, before, now, applied}], edits, unmapped, notes, area?, native?, covered?, twins?}` with `status` one of `new`, `unchanged`, `updated`, `restored`, `orphaned`, `invalid`, `unsupported`, `covered`; `area` is the source's suggested area, `native` the key of another importer's native description of the same device, `covered` what covers a `covered` entry, `twins` the configured devices for the same physical device |
| `POST /api/adopt/resync`     | runs `adopt` with every importer over the file (`resync: true`, `orphan: true`, no new keys): updated and restored devices take the new baseline with the user's edits reapplied, missing ones are marked `source.orphaned`; every device that changed is written and rebuilt. Answers `{importers, entries, written: [key…]}`                                                                                                                                                                                                                                                                                                |
| `POST /api/adopt/:kind/:key` | body `{force?, replace?}`; adopts one entry: a `new` one is added, an `updated` or `restored` one re-synced; nothing else is touched (`orphan: false`). A `covered` one (the same device as another importer's, see importers.md) is `409` with `details: {covered, twins}` unless `force: true`; `replace: true` also disables its twins. `409` for an `unsupported` or `invalid` entry, `404` for an unknown one. Answers the device like `GET /api/devices/:key` plus `entry`                                                                                                                                              |

An orphaned device is never removed by the bridge: removing it is `DELETE /api/devices/:key`.

## Import and export

| Route              | Answer                                                                                                                                                                                                |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/export`  | the configuration file as it is (`content-disposition: attachment`); `?device=<key>` gives `{<key>: device}` for one device                                                                           |
| `POST /api/import` | `{devices: {<key>: device}}` or `{config: {devices: …}}`, with `replace: true` to drop every device not in the body; each device is validated first, then saved and built one by one; `{imported: n}` |

## The event stream

`GET /api/events` upgrades to a WebSocket; every event is one JSON text frame. A client may send
`{"type": "subscribe", "mqtt": false}` to stop receiving MQTT events (and `true` to resume).

| Event        | Fields                                     | When                                                                 |
| ------------ | ------------------------------------------ | -------------------------------------------------------------------- |
| `hello`      | `version`                                  | right after the connection                                           |
| `mqtt`       | `topic, payload, retain, ts`               | every message on a subscribed topic (payload cut at 16 kB)           |
| `attribute`  | `key, endpoint, cluster, attribute, value` | an attribute of a device's endpoint changed (a status, a controller) |
| `log`        | `entry: {id, ts, level, scope, message}`   | a log line                                                           |
| `devices`    | —                                          | the device list changed (created, replaced, removed, imported)       |
| `bridges`    | —                                          | commissioning state or fabrics changed, a window opened or closed    |
| `discovered` | —                                          | an importer's view of its source changed                             |
| `status`     | `mqtt: boolean`                            | the broker connection came or went                                   |
